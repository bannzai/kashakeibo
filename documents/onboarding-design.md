# 課金転換型オンボーディング設計

## アプリ情報

- カテゴリ: 家計簿・個人向け金融
- プラットフォーム: iOS・Android
- コアバリュー: レシートやクレカ・EC明細を撮影・共有するとAIが家計簿の明細を作る
- 設計目標: 初回起動からペイウォールまでの到達率とトライアル開始率を高める
- 主要市場: 日本。日本語・韓国語・中国語は短尺、英語は価値説明とコミットメントを加えた長尺にする

## 参考事例との対応

| 参考事例を構成する要素 | カシャケイボでの対応 |
| --- | --- |
| Misoの価値宣言と出典付き社会的証明 | 撮るだけで記録できる価値宣言と、既存ペイウォールでも使う東証マネ部の調査を表示する |
| ChartDetector AIの進捗表示と大きな単一選択 | 全画面で進捗を表示し、質問は3つの大きな選択肢から1つ選ぶ |
| Plumの金融カテゴリ向けオンボーディング | 機能説明より先に家計管理の悩みと目標を確認する |
| 課金転換型事例のプラン生成演出 | 回答を組み合わせる有限の進捗演出を結果表示の直前に置く |

参照画像は `mobile-ui-references/onboarding/2026-09-01/personal-finance/` に保存する。

## 推奨する型

- 第一候補: パーソナライゼーション。悩み、記録対象、目標を質問し、回答を結果画面へ反映できる
- 第二候補: ソーシャルプルーフ。根拠のないユーザー数やレビューを使わず、既存の出典付き家計簿調査で価値を補強する

## 画面フロー

### 日本語・韓国語・中国語の短尺ファネル

| 順序 | 画面 | 目的 |
| --- | --- | --- |
| 1 | 価値宣言 | レシートやWeb明細を撮るだけで記録できる変化を伝える |
| 2 | 悩みの質問 | 入力負担、支出の見えにくさ、振り返る時間の不足から最優先の悩みを選ぶ |
| 3 | 記録対象の質問 | レシート、Web明細、両方から実際に使う入力導線を選ぶ |
| 4 | 目標の質問 | 支出削減、傾向把握、時間短縮から結果画面に反映する目標を選ぶ |
| 5 | 出典付き調査 | 家計簿で支出が減った人の節約実感を、調査主体・時期・対象人数と一緒に示す |
| 6 | プラン生成 | 回答を利用プランへ変換していることを有限の進捗で示す |
| 7 | 結果とペイウォール導線 | 選択した悩み、記録対象、目標を反映したプランを示し、既存ペイウォールを開く |

### 英語の長尺ファネル

短尺ファネルに次の3画面を加える。

- 価値の詳細: AIが店名・金額・日付・カテゴリを整理することを示す
- 現在の記録頻度: 毎日、週1〜2回、思い出した時だけから現状を選ぶ
- コミットメント: 買い物の時に撮影する小さな習慣を始める意思を確認する

主要市場が日本であり、後段で使わない感情的な質問を増やさない原則を優先するため、英語版も意味のある10画面に留める。長さそのものは実測後に見直す。

## ベストプラクティスとの照合

| 観点 | 対応 |
| --- | --- |
| 価値を先に伝える | 最初の画面で撮影・共有から記録ができる価値を示す |
| 機能ツアーを強制しない | 操作説明の列挙をせず、通常画面の高度な機能説明は通常利用時に残す |
| 最初からパーソナライズする | 悩み、記録対象、目標を結果へ反映する |
| 早期の成功を作る | 回答から自分向けプランができることを最初の成果とする |
| 権限を文脈内で求める | カメラ・写真権限はオンボーディングで要求せず、実際の撮影時に既存導線から求める |
| 進捗を示す | 全画面で現在位置と全画面数を表示する |
| 次の行動を明確にする | 結果画面の単一ボタンからペイウォールへ進み、閉じた後は月次画面へ移る |
| 通常利用へつなぐ | ペイウォールを閉じても無料枠で月次画面と撮影機能を使える |

## 計測

| ファネル上の出来事 | イベント |
| --- | --- |
| 初回起動 | Firebase Analyticsの自動収集 `first_open` |
| オンボーディング開始 | `onboarding_start` |
| 各ステップ表示 | `onboarding_step_view` |
| 回答 | `onboarding_answer` |
| オンボーディング完了 | `onboarding_complete` |
| 1画面目のシステム戻るで閉じる | `onboarding_close` |
| ペイウォール表示 | `paywall_open` |
| ペイウォールを閉じる | `paywall_close` |
| トライアル開始 | RevenueCatの購入結果がtrialの時に `trial_start` |
| 通常購入完了 | RevenueCatの購入結果がtrial以外の時に `purchase_complete` |

最初に確認する指標は、オンボーディング完了率、ペイウォール到達率、トライアル開始率とする。英語の長尺とその他言語の短尺は `funnel_variant` で分けて比較する。

## 課金構成

価格、通貨、無料トライアル期間はストアとRevenueCatが正を持つため、オンボーディングには固定値を置かない。Issue 76で別途検討とされた「無料短期と少額長期の2択」は今回変更せず、既存Offeringを表示する。
