# カシャケイボ (Kashakeibo)

スクショ・写真を撮ったら記録される家計簿。Web ページ上のクレカ・EC の明細、レシートから、AI (Gemini vision) が明細を作り出して家計簿として登録する。

- 企画・調査の出典: https://github.com/bannzai/IdeaMemo/issues/188 (需要・競合・命名・技術スタックの実測調査と決定の全記録)
- 期限: Shipaton 2026 応募。締切 2026-09-30、審査提出を考慮して 2026-09-20 頃までにリリース

## コンセプト

口座連携型家計簿の構造的な隙を突く。連携 API は金融機関側の仕様変更で恒常的に壊れ、PayPay のように連携で取れない決済が主役になりつつある。「画面に見えているものをスクショすれば取り込める」方式はこの構造問題に依存しない唯一の汎用入力であり、連携メンテコストもゼロ。認証情報を預からないため、電子決済等代行業の規制圏にも入らない。

「連携しない・預からない・スキャン原価に対応した無料枠設計」が収益と設計が一体の物語 (Shipaton HAMM 賞の主戦略)。

## MVP スコープ (入力3系統 + 信頼の核)

1. 紙レシート撮影 → AI 解析で明細化
2. カード明細・EC 購入履歴のスクショ取込 (共有 Extension 経由) → AI 解析で明細化
3. 手動での明細登録 (スクショが無い現金支出の受け皿)

- 重複検知: カード明細スクショとレシートの二重計上はこの方式固有の問題。v1 は金額+日付+店名のヒューリスティック+手動マージ
- 画像と明細の紐付け: 「元の画像に戻れる」は AI 解析の誤りをユーザーが自力で正せる保険。不要画像の削除、明細の計算対象からの除外も可能にする
- 出所記録: 自動取込か手調整かを記録し、後から追えるようにする
- 月次集計 (収入・支出・カテゴリ内訳)

### MVP で落とすもの

- レシートの位置情報・スポット登録 (差別化に効く前に工数を食う)
- Keychain 保存のログイン情報での Web 自動取得 (利用規約・審査・セキュリティリスクが重く、「連携しないから壊れない」という構造的な売りを自ら破壊する。共有 Extension で摩擦を減らす方向が筋)
- 共有機能

## 課金設計

Cal AI が実証した「スキャン数回でハードペイウォール」型。無料 = 月10スキャンまで (LLM 原価の上限を固定)、プレミアムでスキャン無制限+全履歴。

## ストア表記

- JP タイトル: `カシャケイボ - スクショを撮るだけAI家計簿`
- US タイトル: `Kashakeibo: Snap & Track Budget`
- 由来: カシャ (シャッター音・iPhone のスクショ音) + ケイボ (家計簿)。"kakeibo" は英語圏で書籍化されるほど認知のあるメソッド名で、US でもそのまま通じる
- 衝突チェック: JP「カシャケイボ」・US「kashakeibo」とも該当なし (2026-08-16 iTunes Search API 実測)

## 賞戦略 (Shipaton 2026)

- 主: HAMM (収益化の物語)。マネーフォワードの連携破綻レビューとの対比で語る
- 副: #BuildInPublic (ASO 埋没リスクの保険として発信が必須)
- Grand Prize は狙わない (成長を示す期間が足りない)

## リスクと対策

1. ASO 埋没 → 「スクショで読み取る」を一言で伝えるストア素材 + #BuildInPublic 発信を初日から
2. 解析精度への期待値管理 → 画像との紐付け+手修正 UI が保険。対応フォーマットを絞って謳う
3. LLM コスト → 無料枠をスキャン回数で区切る (課金設計と一体)
4. スイッチングコスト → 既存アプリからの CSV インポートが乗り換え導線として効く
